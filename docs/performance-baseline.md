# 性能基线

> **这份文档只记录数字，不做性能承诺。**
> `iteration-roadmap.md` I0 要求"把实测数字写进文档，而非宣称"——
> 数字会随硬件、SDK、数据形状变化，承诺会变成无法兑现的债。
>
> **怎么复现**：`dotnet run --project spike/Dougong.Agent.Comparison -c Release -- perf`
> 这个套件只输出数字，不参与通过/失败判定，因此不在 `scripts/all-checks.sh` 里。

## 一、大会话（1000 条历史）

每条约 220 字节（一个 index + 200 字符文本），追加后重新打开并全量重放。

| 项 | 实测 |
|---|---|
| 打开会话文件 | 13 ms |
| 追加 1000 条 | 716 ms（0.72 ms/条） |
| 重放 1000 条 | 22 ms（0.02 ms/条） |
| 文件大小 | 263 KB |

**怎么读这组数字**

- **追加是重放的 33 倍**，符合预期：每次追加都做 `Flush(flushToDisk: true)`，
  这是提交屏障的成本，不是缺陷。想更快就得放弃落盘保证——那是另一个取舍。
- 0.72 ms/条意味着**一次工具调用的持久化开销远小于一次模型调用**（后者通常
  数百毫秒到数秒）。因此在真实会话里，存储不是瓶颈。
- 重放 0.02 ms/条：1000 条历史恢复只要 22ms，**会话长度不影响恢复体验**。

## 二、长会话（插件反复装卸）

同一插件连续 load/unload N 轮。关心的是**是否线性**——泄漏会表现为超线性增长。

| 轮次 | 实测 | 每轮均摊 |
|---|---|---|
| 1 | 66 ms | 66.1 ms |
| 10 | 50 ms | 5.0 ms |
| 20 | 110 ms | 5.5 ms |

（三次独立运行的数字一致：1 轮 65–67ms，10 轮 47–54ms，20 轮 105–115ms）

**第一轮有约 60ms 的固定开销**（JIT、首次 ALC 加载、首次反射），之后每轮约 5ms。

**线性性验证**：以 20 轮减去预热推算边际成本约 2.3 ms/轮，
预测 20 轮 110ms、实测 110ms（吻合）。

**但 10 轮的预测偏高**（预测 87ms、实测 50ms）。这说明预热不是简单固定值——
10 轮时部分预热成本已被摊薄但尚未完全体现。**这里如实记录不一致，不强行解释。**

**结论**：20 轮没有超线性迹象，与 `KernelRepeatedCycleTests` 的泄漏断言一致。
但轮次再大（50+）未测——需要时再补。

## 三、并发会话（4 会话 × 50 次工具执行）

同一工作区，各会话用**不同资源键**（`file:<ws>/fN.txt`）声明只读操作。

| 项 | 实测 |
|---|---|
| 顺序执行 | 6 ms |
| 并发执行 | 1 ms |
| 加速比 | 6.00× |

**怎么读**：并发确实快于顺序，说明资源级读写键在工作——不同资源的读可以并行。
若锁是"整个工作区一把"，并发会比顺序更慢（上下文切换开销）。

**这组数字的局限**：执行体是空的（只取锁、不放实际 IO），因此测的是
**锁本身的代价**，不是真实工具的性能。绝对数字很小（6ms/200 次），
意义在于"并发不退化"而非"并发有多快"。

**未测**：同一资源键上的争用（那会串行，代价取决于持锁时长）。
真实场景里持锁时间由工具本身决定，基线无法给出通用数字。

## 四、这份基线没覆盖什么

| 未覆盖 | 原因 | 什么时候该补 |
|---|---|---|
| 真实 provider 的端到端延迟 | 依赖网络与模型，不属于本 SDK 的基线 | 已由 M1 的 LiveRun 记录过（含 provider/模型/token） |
| 大量并发会话（>4） | 当前宿主形态是单会话 CLI + 多会话 ACP | 桌面宿主同时开多个会话时 |
| 内存占用 | 未测量。ALC 回收已由 WeakReference 断言覆盖，但峰值 RSS 没有 | 出现内存相关问题时 |
| 50 轮以上的装卸 | 20 轮已足够暴露线性问题 | 需要长跑验证时 |
| 上下文压缩的耗时 | 一次摘要 = 一次模型调用，延迟由 provider 主导 | 无需单独测 |

## 五、怎么用这些数字

1. **回归对比**：改动涉及存储、生命周期或资源锁时，跑一次 `-- perf` 与本文对比。
   数量级变化（例如追加从 0.72 变成 7 ms/条）需要解释。
2. **不要拿它做承诺**。对外说"支持长会话"时，依据是"1000 条历史恢复 22ms"
   这个实测，不是"性能很好"这种形容。
3. **换环境要重测**。这份数字绑定上面那张环境表。
